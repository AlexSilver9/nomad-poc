# User Tokens

Guide for creating and managing personal Nomad and Consul tokens for cluster operators.

Each operator gets two tokens: one for Nomad, one for Consul. Tokens are named (tied to a person) and assigned roles rather than policies directly — updating a role propagates to all token holders without re-issuing tokens.

**Prerequisite**: ACL must be bootstrapped first (`bootstrap_acl.sh`). See [ACL_IMPLEMENTATION.md](ACL_IMPLEMENTATION.md) for the full ACL setup procedure.

---

## Available Roles

### Nomad roles

| Role | What it grants |
|---|---|
| `deployer` | Submit, dispatch, and stop jobs; exec into allocations; read logs and fs; node_pool write |
| `readonly` | Read job status, logs, fs, nodes, agents — no writes |
| `operator` | Drain and re-enable nodes, alloc lifecycle operations |

### Consul roles

| Role | What it grants |
|---|---|
| `readonly` | Read nodes, services, agents, KV store |
| `readwrite` | Write nodes, services, agents, KV store |

## Defining Users

Users are declared in [`aws/acl/users.json`](../aws/acl/users.json). Each entry maps a username to role assignments in both Nomad and Consul:

```json
[
  {
    "username":     "alice",
    "nomad_roles":  ["deployer", "operator"],
    "consul_roles": ["readwrite"]
  },
  {
    "username":     "bob",
    "nomad_roles":  ["deployer", "operator"],
    "consul_roles": ["readwrite"]
  }
]
```

Typical role combinations:

| Access level | Nomad roles | Consul roles | Use case |
|---|---|---|---|
| Full operator | `deployer`, `operator` | `readwrite` | Engineers with full operational access |
| Deployer only | `deployer` | `readwrite` | Engineers deploying jobs |
| Read-only | `readonly` | `readonly` | Monitoring, audit, junior access |

## Creating Tokens

Run on a cluster node after `bootstrap_acl.sh` has completed:

```bash
ssh -i ~/workspace/nomad/nomad-keypair.pem ec2-user@<NODE>

export NOMAD_TOKEN=<nomad-management-token>
export CONSUL_HTTP_TOKEN=<consul-management-token>
./create_user_tokens.sh
```

Management tokens are in `aws/acl/bootstrap-output.txt` (generated by `bootstrap_acl.sh`).

The script runs three phases:

1. **Nomad roles** — creates `deployer`, `readonly`, and `operator` roles (idempotent — skips if already present)
2. **Consul roles** — creates `readonly` and `readwrite` roles (idempotent)
3. **User tokens** — creates one Nomad token and one Consul token per entry in `users.json`. Appends all tokens to `~/acl/user-tokens-output.txt` (gitignored).

After the script finishes:
- Transfer `~/acl/user-tokens-output.txt` to the password manager
- Delete the file from the node

---

## Adding a New User

1. Add an entry to `aws/acl/users.json` and push to the branch
2. SSH to a cluster node and re-run `create_user_tokens.sh`

Existing tokens are not touched — the script skips users that already have a token.

## Changing a User's Roles

Update `users.json` for documentation purposes, then update the token directly:

```bash
# Find the accessor ID
NOMAD_TOKEN=<mgmt> nomad acl token list -json | jq '.[] | select(.Name == "alice")'
CONSUL_HTTP_TOKEN=<mgmt> consul acl token list -format=json | jq '.[] | select(.Description == "alice")'

# Update Nomad token
NOMAD_TOKEN=<mgmt> nomad acl token update \
  -accessor-id=<accessor-id> \
  -role-name=deployer \
  -role-name=operator

# Update Consul token
CONSUL_HTTP_TOKEN=<mgmt> consul acl token update \
  -id=<accessor-id> \
  -role-name=readwrite
```

## Revoking Tokens

Revoke by username — runs on a cluster node:

```bash
export NOMAD_TOKEN=<mgmt>
export CONSUL_HTTP_TOKEN=<mgmt>

./revoke_nomad_user_tokens.sh <username>
./revoke_consul_user_tokens.sh <username>
```

Both scripts are idempotent: if no token exists for the username, they exit cleanly.

## Using Tokens

### Nomad CLI

```bash
export NOMAD_TOKEN=<token>
nomad status
nomad job run services/web-service/job.nomad.hcl
```

Or per-command: `nomad status -token=<token>`

**Which token to use:**
- Viewing job status, logs, nodes → read-only token
- Deploying and managing jobs → deployer token
- Creating/modifying ACL policies and tokens → management token

### Nomad UI

Click the person icon (top right) → **Log in** and paste the token. The read-only token gives a browsable view. The deployer token enables job operations. The management token gives full access including the `Administration` option in the left side menu panel (ACL panel).

### Consul CLI

```bash
export CONSUL_HTTP_TOKEN=<token>
consul members
consul catalog services
```

Or per-command: `consul members -token=<token>`

**Which token to use:**
- Browsing services, nodes, health checks, KV → operator readonly or readwrite token
- Creating/modifying ACL policies and tokens → management token

### Consul UI

Click **Log in** (top right) and paste the token. Operator tokens give access to services, nodes, health checks, and KV. The management token additionally exposes the ACL panel.
